# 大型任务执行规范

跨模块、多阶段、需长期执行或逐文件审计的工作从[任务模板](../tasks/TEMPLATE.md)建立任务记录，在[任务索引](../tasks/PROGRESS.md)登记。任务记录保存当前进度与证据，索引提供入口。下列流程可按实际批次重复，每个实施阶段在任务记录中写明输入、输出、完成条件和恢复起点。

## 执行顺序

1. **需求分析**。输入为用户请求与既有决定。输出为目标、非目标、交付物、工作范围和限制。完成条件是每项明确要求都有对应交付或验收项，可从任务记录恢复原范围。
2. **代码调研**。输入为当前工作区、历史计划与既有证据。输出为相关入口、调用链、数据契约、可复用实现、验证入口和未知点。完成条件是能定位受影响的职责与既有成果，记录工作树或版本基线以及尚待确认的影响。
3. **任务拆分**。输入为范围和调研结果。输出为有顺序和依赖的阶段，每阶段列输入、输出、独立完成条件和恢复起点。完成条件是所有要求都能映射到阶段，依赖与可先推进的工作已写明。
4. **制定验收标准**。输入为各阶段的预期结果。输出为可检查的验收项、验证方式、环境和预期结果。完成条件是每项都有唯一编号、验证类型和初始结果记录，自动检查无法判定的事项已标明。
5. **分阶段实施**。输入为阶段计划和上次检查点。输出为该阶段所需的代码、记录或其他交付物。完成条件是产物可从正常入口检查，期间发现的问题已记录位置、影响和后续处理。
6. **阶段验证**。输入为该阶段的产物和完成条件。输出为实际命令或复核步骤、环境、结果和证据位置。完成条件是阶段验收通过。失败时记录复现步骤和预期差异，优先修复后重测，保留有意义的失败记录。遇外部阻塞时可继续与其无依赖的工作。
7. **更新进度**。输入为已验证的工作与未解决事项。输出为更新的任务记录和索引。完成条件是从文件能找回批次、证据、剩余范围、阻塞和具体下一步。阶段验收通过后勾选该阶段，条件允许时直接进入下一阶段。较长阶段每批保存一次检查点。
8. **最终验收**。输入为实际交付物、全部验收项和当前版本证据。逐项核对，通过后记录结果，将任务和索引同时更新为 `COMPLETED`，再运行任务校验。若校验未通过，恢复未完成状态，修复并重验。任一必需项缺证、失败或待实机核验时，记录原因并继续处置。阶段完成、代码生成和口头总结均不能作为整项任务通过依据。

新发现记录在当前任务的已完成工作、剩余工作或阻塞中，注明证据、影响和处置。需要改变明确的目标、范围或验收条件时，保留原要求，记录提议及用户决定后再修改。

## 进度、状态和恢复

- `PENDING`：已登记，等待启动。写明前置依赖与启动动作。
- `IN_PROGRESS`：有可推进的调研或实施工作。
- `VERIFYING`：交付物进入验收，待检查或补证。失败需要修改时回到 `IN_PROGRESS`。
- `BLOCKED`：存在当前无法自行解除的依赖，且已推进可独立完成的工作。写明阻塞对象、失败证据、已尝试的办法、解阻条件与恢复步骤。
- `COMPLETED`：阶段均完成、所有验收项有通过记录，剩余工作、阻塞原因、下一步动作均为 `无`。发现新失败或证据失效时重新开启任务并同步索引。

新会话先从索引定位原任务。核对任务范围、Git 工作区、最后一次验证的版本或文件状态和证据位置，再从「下一步动作」恢复。复用仍适用的已验证成果，重验受到后续改动影响的部分。用户叫停、执行预算耗尽或工具暂时不可用时，保留进度所对应的状态，写清中断点、剩余工作和下一步。只有存在实际阻塞且当前无其他可推进的工作时使用 `BLOCKED`。

## 验证类型

- `AUTO`：可重复运行的本地检查、类型检查、单元测试和模拟测试。记录命令、运行环境、结果以及可复现样例或日志。使用假 ADB 和 CAN 模拟模式仅能支持对应的离线结论。
- `MANUAL`：不可自动判定的语义审查、操作体验或平台检查。记录复核者、环境、步骤及可追溯的观察结果。
- `HARDWARE`：依赖真实车机、USB、CAN 适配器或台架，不可由任务脚本自动验收。仅在适用且获准的设备和安全环境中执行，记录实际设备、平台、设置、操作和观测证据。缺少条件时留 `PENDING` 并写明恢复条件。

已有业务验证入口包括 [后端 pytest 和便携包检查](../README.md)、`node --test tools/ui-test/*.test.mjs`、`pnpm check` 和 `pnpm build`。按变更范围选用，按实际运行情况记录测试结果，区分本地模拟、Windows 环境和真实设备。任务校验脚本只核对结构、证据记录及覆盖，真实执行和结论由证据支撑。

## 运行任务校验

从仓库根目录运行，使用项目已有的 Python 3.11+ 和 Git。

```sh
python3 scripts/verify_tasks.py
python3 -B -m unittest discover -s scripts -p 'test_*.py' -v
python3 scripts/verify_tasks.py --audit-coverage CODE-AUDIT-001
```

默认检查所有任务、索引和验收记录，并统计审计覆盖。未完成审计可保存缺口并通过结构校验。指定 `--audit-coverage 任务ID` 时列出该审计的缺失、部分审阅和已变更文件，有缺口返回非零。任何标记 `COMPLETED` 的审计自动使用相同的完整覆盖要求。任务文件、验收结果和审计台账的具体格式见任务模板。

脚本依据 Git 跟踪和未忽略的新文件独立枚举当前实际存在的第一方文件，包含测试、工具、配置和文档。枚举略过 `backend/vendor/` 第三方分发物和 `tasks/` 下的 Markdown 任务记录，避免任务台账为自己记录内容摘要。经用户确认的整文件排除仍需匹配独立枚举，并在对应任务范围和台账留痕。其他忽略范围由 Git 的忽略规则决定。审计范围内的删除或改名须保留必要的历史证据，并更新台账中的现行路径。
