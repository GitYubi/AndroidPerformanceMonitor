# 车机页面地图与元素操作设计

版本：评审稿 v1 · 2026-09-16。本文是目标设计，尚未实现或在车机验证。依据当前工作区代码与本次需求；没有读取另一个对话的完整历史。交互样例使用虚构设置页面和 ID。

## 1. 用户最终得到什么

在 UI 测试工作台中增加长期保存的「页面地图」。左侧展示业务页面及其元素，中间显示设备实时画面，右侧显示选中对象的属性、定位规则和入口路径，下方展示执行进度。

用户可以自动发现页面，也可以边操作边补录。用户命名、保存的页面和元素跨扫描、跨重启保留。右键页面可跳转；右键元素可先定位到所属页面，再点击或设置状态。原始 Android 控件树作为检查工具保留，不充当业务导航树。

首版默认沿用电脑端 FastAPI + Node 执行器 + ADB 的形态，设备控制抽象成 Adapter。没有必要先自研 APK；后续接入常驻 Agent 不改变页面、元素与导航的数据契约。视频通道独立，不作为页面身份依据。

## 2. 当前实现与目标的差距

代码观察基于本次读取的工作区快照，其他对话可能继续修改它。

- `client/src/components/PageStructure.tsx`：从单轮扫描的 graph-page / graph-edge 事件按深度展示页面；点击加载该次扫描的控件 JSON。没有独立的页面/元素库、命名、右键执行或路径规划。
- `tools/ui-test/hierarchy.mjs`：通过 ADB dump 获取树；fingerprint 由节点包名、类名、ID、文字和描述生成。已排除 summary 和输入框文字等部分动态内容，但其他动态文字和滚动可见节点仍影响身份。selector 为 package/className/resourceId/label 的组合，执行时要求唯一；没有 XPath、容器范围或长期元素身份。
- `tools/ui-test/explore.mjs`：已有 DFS、节点去重、跳转记录、返回校验和预算。自动入口识别偏向带 `/title` 子节点的若干容器类；滚动区域仅标记覆盖缺口。页面改变主要依据 fingerprint 改变，不能可靠区分页面、弹窗、滚动与状态变化。
- `backend/app/ui_testing.py`：已有 cases、runs、events 和产物存储，以及 UI 运行的设备锁。新工作台应复用任务和证据机制，但必须让手动控制、扫描、录制和执行共享同一个写入仲裁入口。

这些组件是可复用基础；现有扫描报告不能直接升级为“已验证可回放的页面地图”。

## 3. 必须成立的产品规则

1. 页面、入口元素、普通操作元素是不同对象。入口定位器属于来源页，跳转目标是另一页面。
2. 页面用永久 pageId 标识；同页开关状态、动态数值和滚动位置不产生新的 pageId。
3. 元素用永久 elementId 标识；名称只是可编辑别名。改名不能改变定位器或路径引用。
4. 每个可执行元素必须有 ownerPageId。保存父子显示层级不等于保存了到达路径。
5. 跳转路径是已观测、可验证的有向边序列；页面地图底层为图，左侧展示其树形投影。
6. 每次执行先识别页面，再定位元素；定位必须在正确页面、屏幕和窗口范围内唯一。
7. 点击成功仅表示输入已送出；页面跳转、开关设值的成功必须由后置条件确认。
8. 未知当前页、多个候选页面、元素重复、路径失效都不得自动选第一个继续。
9. 扫描与具体操作分开：扫描发现入口与元素；用户明确点击的操作可执行。未知控件不能只因 clickable 就当成导航入口。
10. 所有结果标明“候选 / 已发现 / 已验证 / 待修复”；不把预算耗尽显示成全车遍历完成。

## 4. 工作台交互

### 布局与选择行为

- 顶栏：设备、目标屏幕、地图库/适配版本、连接状态、发现页面、录制路径、停止。
- 左栏：搜索、页面业务树；页面下可展开已保存元素。用文字区分页面、入口引用、按钮、开关、弹窗。同一页面的其他入口显示为引用节点，避免复制和无限递归。
- 中栏：实时画面；已保存参考截图另开明确标识的预览。只有当设备正在选中元素所属页面且定位唯一时，才在实时画面高亮；不会把历史坐标投到当前画面。
- 右栏：名称、所属页面、主定位器、备选定位器、当前匹配数、关联入口、最后验证版本和时间；原始控件树为检查页签。
- 底栏：来源页 → 入口 → 目标页的执行轨迹、每步结果、失败证据。

单击树节点只查看，不驱动车机。右键或节点旁的“更多”按钮打开相同菜单，兼顾无法右键的设备。名称编辑是独立操作。

### 菜单契约

- 页面：跳转到此页、查看入口路径、重命名、重新验证、补充入口。
- 按钮：跳转到所属页、定位并高亮、点击、重命名、修复定位器。
- 开关：跳转到所属页、开启、关闭、点击一次、重命名、修复定位器。没有可读状态时禁用开启/关闭并解释原因；点击一次仍可用，但结果不能伪称状态已确认。
- 候选入口：查看证据、录制/试走并验证、标记为操作元素、忽略。
- 路径失效：显示具体失败的边，提供从当前页补录；不默认覆盖旧定位器。

“定位并高亮”会先导航；“查看属性”不会。“跳转到此页”默认选择验证过的可用路径，可在路径面板手动选另一条。用户指定路径时不静默替换。

### 保存一个元素

在实时画面或原始树中选控件 → 将截图坐标映射到同次快照的节点 → 确认所属页面 → 生成并校验定位器 → 命名 → 保存。若当前页未建档，先保存页面草稿，再录制可达入口。没有可用路径的元素仍可存草稿，但标记“仅当前页可用”，不承诺任意页面一键直达。

## 5. 数据模型

推荐扩展现有 SQLite UI 存储；逻辑上分长期地图库与不可变运行证据。所有库对象含 schemaVersion、revision、createdAt、updatedAt；引用使用 ID，不能使用名称或数组下标。

- **MapProfile**：mapId、名称、设备/车型适配信息、系统构建、应用版本集合、语言、显示配置、adapterCapabilities。serial 是运行绑定，不是地图库永久身份。版本不匹配时先重新验证。
- **Page**：pageId、mapId、name、kind(page/tab/dialog)、识别规则、canonicalParentEdgeId、status。页面没有唯一的入口 resourceId；入口在各条 Edge 上。
- **PageVariant**：variantId、pageId、前提条件与局部锚点。开关值和普通列表滚动是 Observation 状态；改变可执行动作/前提的界面变体才建 Variant。页签内容作为独立导航目标；模态对话框绑定宿主页，明确进入和退出动作。
- **Element**：elementId、ownerPageId、name、role(entry/button/switch/input/scrollContainer)、locatorSet、stateReader、supportedActions、revealPlan、status、revision。
- **LocatorSet**：主规则、经过验证的备选规则、page/window/container 范围、expectedCount=1、验证证据、适用版本。XPath 标记具体语法/引擎版本。坐标不是稳定 locator。
- **Edge**：edgeId、fromPageId、toPageId、triggerElementId 或已验证启动动作、前提条件、动作序列、目标断言、恢复策略、验证状态、耗时与失败统计。返回边单独验证，不能假设每次 Back 都返回父页。
- **Observation**：observationId、时间、serial/display/window、采集能力、XML/截图引用、采集起止时间、识别结果、滚动与开关状态、结构摘要。记录截图和树是否同一稳定窗口内采集，不假装二者原子同步。
- **Execution**：runId、请求意图、mapRevision、plan、每步前后 Observation、定位候选数、命令发送状态、后置验证、最终状态。

引用约束：Edge.triggerElement 必须属于 fromPage；树的 canonicalParent 不得形成环；删除页面有入边或元素时默认归档，显式修复依赖后才删除。合并页面保留旧 ID 映射和证据；拆分时重新绑定边和元素。

页面身份和快照去重使用不同机制：pageId 是永久身份；observationHash 只用于快照重复检查，不作为 pageId。

## 6. 页面识别

输入是指定 display/window 的稳定快照，输出为 matched(pageId, variantId)、unknown、ambiguous 或 unstable，而不是强制返回某个页面。

1. 先限定 mapProfile、display、目标应用窗口及可用的包名/Activity 元数据。Activity 只是辅助，不能等同于页面。
2. 检查页面的 requiredAll、requiredAny、forbidden 锚点。锚点可以是稳定 ID、页面标题、选中页签及容器关系；动态时钟、媒体标题、温度等明确排除。
3. 必须锚点通过且仅一个候选满足接受规则时才能确认；相似度用于排序待检查候选，不能单独授权点击。多个页面共用标题时补充区域/容器特征。
4. 滚动不会建立新页面。若所有识别锚点都被滚出视口，只能依靠事先验证过的视口变体规则；否则返回 unknown，不能仅因“刚才还在此页”就确认。
5. 弹窗作为覆盖层识别，不能忽略后点击底层。只有已建模的关闭动作可以自动处理；未知弹窗停止并显示证据。

稳定等待使用页面相关锚点及目标区域连续一致，不等待全屏每个动态文字都不变；候选默认参数为两次相隔至少 300ms 的有效观察、单步最长 8s，可按适配配置。它们是待实机调优参数，不是已测性能保证。点击前必须更新定位并检查屏幕旋转、窗口和 bounds 有效性。

## 7. 定位器与滚动

生成时依次尝试：页面内唯一 resourceId → 容器范围内 resourceId → ID/描述/文本/类型的稳定组合 → 关系型 XPath。绝对下标 XPath 只作脆弱定位规则，显式标记并在执行前重验。

resourceId 与 XPath 都没有跨页面唯一保证。命中数量必须在 ownerPage + window + container 范围内计算。首选规则命中 0 可尝试已验证备选；命中多个或不同备选指向不同对象时停止，不投票猜测。重命名与 locator text 分开。

revealPlan 表达“在哪个滚动容器、向哪个方向、怎样发现目标”，不保存固定屏幕坐标或唯一滚动次数。执行时先查目标；找不到才有界滚动，每次重读、去重视口，直到找到、边界不再变化或预算耗尽。虚拟列表使用稳定条目标识及容器关系，不能依赖节点序号。每次滚动后重新定位。

无节点的区域首版标记“结构不可访问”，支持手工记录说明。图像/OCR 定位可作为后续独立适配能力，不能静默回退成坐标点击并标记为结构定位成功。

## 8. 自动发现与人工补录

完整入口包括“自动探索”“引导录制”“导入旧扫描”。三者写入同一数据模型。

自动探索工作单元为 (pageId, variant, viewport, candidateElement)，而非全局 fingerprint。对当前页采集所有可见候选、逐容器滚动补充，分类为已知导航入口、疑似入口、状态操作及未知控件。入口外观只能产生候选，实际跳转后才能确立 Edge。开关整行不能因可点击而自动点击。

对允许的导航候选执行：记录来源 → 定位并点击 → 等待 → 识别目标 → 保存观察与边 → 继续探索 → 用已验证返回/重建路径恢复。首次成功是“已发现”；从已知入口重放并验证后升级“已验证”。不变页记录无跳转；循环边保存但不递归；恢复失败保留断点，不继续用错误父页探索。

未知入口可由用户在引导录制中点击并标注“打开页面”或“操作控件”。工具记录前后快照及元素来源；仅观察界面变化不能证明它是无副作用的入口。车辆状态、连接外设等前提单独记录，当前不满足则标记条件未满足。

发现任务支持暂停、取消、断点继续和包名/页面/动作/时间/滚动预算。覆盖报告给出发现页面数、已验证边数、候选入口、因条件/预算/定位失败而未探索的区域；不知道总页数时不显示覆盖率百分比。

## 9. 路径规划与稳定回放

统一入口是意图：navigate(pageId)、locate(elementId)、click(elementId)、setChecked(elementId, desired)。元素操作统一转换为 ensurePage(ownerPageId) + reveal + resolve + execute + verify，前端不拼脚本。

执行流程：取得设备写锁 → 固定地图版本 → 读取并识别当前页 → 检查前提 → 规划已验证可用边 → 每步校验来源、定位、执行、确认目标 → 执行最终动作 → 校验结果 → 释放锁并保存证据。

规划优先满足条件、验证有效且失败率低的路线，再比较预计耗时和步数。不会为了较短路径采用未验证边。当前页就是目标页时跳过导航，但仍重新确认窗口和元素。当前页未知时可使用已配置并验证过的根入口（例如特定设置启动动作）；根入口本身也必须验证到达。没有根入口时返回需要用户回到已知页面，不盲发 Back。

setChecked：读取可靠状态；已等于目标则成功且不点击；否则点击一次，重新读取验证。状态不可读则返回状态不可确认，不执行猜测式设值。开关开启/关闭不会默认恢复，恢复原状态属于独立测试意图。

click：按钮有后置断言时按断言验证；没有时只报告“点击已发送，业务效果未验证”，与完整成功区分。

恢复：失败后先重新采集。确实已达预期目标则继续；仍在来源页且动作明确可安全重复时，允许配置的一次重试；其他已知页可有界重规划一次。非幂等点击在响应丢失时标记 outcome_unknown，不重发。只读观察可以重试。所有预算按整个任务累计，取消后不再发下一条命令；正在执行的设备命令可能已生效，记录最后观察。

运行状态：queued → identifying → planning → navigating → locating → acting → verifying → succeeded / action_sent / blocked / failed / outcome_unknown / cancelled / interrupted。blocked 附 page_unknown、page_ambiguous、precondition_missing、locator_ambiguous、route_stale 等原因；进程崩溃后的未完成动作不能自动当作没发生。

同一 serial 先采用设备级单写锁，所有屏幕共享；读取和视频可继续，采集负载需要节流。自动任务中手动输入应显式“接管并暂停”，或检测外部输入造成的页面偏离后暂停；不能与测试执行器同时发命令。

## 10. 模块与接口草案

后端管理长期模型、地图版本、设备写锁和任务；Node 层提供 Adapter、识别、定位、探索和执行引擎，保持现有 Node runner 集成方式，避免 Python 与 JS 各维护一套定位语义。

Adapter 能力契约：getCapabilities、observe、resolve、tap、scroll、back、launch、readState、screenshot；不支持的方法明确返回 unsupported。observe 返回 display/window 及采集时间。视频另走帧通道。XPath 引擎必须选择、锁版本并用真实 XML 验证，不能假设现有解析器已支持。

建议新增模块（待实施）：`backend/app/ui_map.py`、`ui_map_store.py`、共享 device command coordinator；`tools/ui-test/navigation/{recognizer,locators,planner,executor,discovery}.mjs`；前端 `PageMapWorkbench`、`PageMapTree`、`ElementInspector`、`NavigationTrace`。

接口草案：

- `GET/POST /api/ui/maps`，`GET /api/ui/maps/{id}/graph`：地图及树投影。
- `POST /api/ui/maps/{id}/observations`：采集快照及识别结果。
- `POST /api/ui/maps/{id}/pages|elements|edges`：保存，引用 observationId 作为证据。
- `PATCH /api/ui/maps/{id}/objects/{objectId}`：改名/修正规则，携带 expectedRevision；冲突返回 409。
- `POST /api/ui/maps/{id}/discoveries`：范围、预算、适配配置；返回任务 ID。
- `POST /api/ui/maps/{id}/recordings`：记录导航，结束后校验再保存。
- `POST /api/ui/maps/{id}/plans`：生成可审阅路径，返回 revision 和前提。
- `POST /api/ui/maps/{id}/executions`：serial、displayId、intent、targetId、desiredState、mapRevision、requestId；返回 runId。
- `GET /api/ui/runs/{id}/events`、`POST .../cancel`：沿用现有运行入口，增加事件类型。

requestId 防止前端双击/网络重试创建重复操作，但不能保证设备输入 exactly-once；命令响应丢失仍按 outcome_unknown 处理。保存计划不是执行授权令牌；实际执行必须重新识别、检查版本和前提。

## 11. 与现有数据的兼容和实施顺序

旧扫描记录只读保留。导入器把 graph-page 变成候选 Page，把 graph-edge 变成候选 Edge，保留原 XML、selector、时间和来源运行。旧 fingerprint 只作来源引用，不强行合并页面。缺 XPath、所属页或重新验证证据时显示待补充。

阶段一：先完成“人工保存 → 页面/元素命名 → 录制入口 → 右键导航/设值 → 重启后可用”的闭环。保留实时画面和原始控件树，接入地图库和统一执行器。这是首个验收里程碑。

阶段二：用相同模型接入自动探索、滚动、多入口、返回恢复、失败修复及旧数据导入。自动探索结果进入持久地图，而非独立扫描展示。

阶段三：针对目标车机验证多屏、窗口与设备 Agent 适配，再考虑自绘区域的独立定位方案。是否部署 Agent 取决于实机 dump 延迟、节点可见性和现有帧通道稳定性，不能仅因其他工具似乎使用 ATX 就先重写底层。

## 12. 评审与验收场景

以下是必须验证的行为，不是已通过的测试：

1. 保存“系统设置 → 显示设置 → 自动亮度”，从另一已知页面选择开启：逐步到页、唯一定位、设为开、验证。
2. 自动亮度已开：再次开启，最终操作零次点击；点击一次则反转一次。
3. 重命名为“屏幕自动调光”：路径和定位仍可用，重启后名称与关系保留。
4. 同一 ID 对应两行开关：使用容器关系唯一定位；仍歧义则停止且零点击。
5. 目标在滚动区下方：在正确容器内有界查找；重复视口或预算耗尽后明确失败。
6. 时钟/温度变化、开关改变、滚动：不新增业务页面；两个共用布局的不同页签不能被误合并。
7. 同页存在两个入口：保存两条边，树显示引用；其中一条失效后可选择另一条已验证路线。
8. 弹窗、人工操作和跨包跳转：识别新状态后暂停或采用已验证处理，不点击遮挡后的旧坐标。
9. 命令发送后断线：重新观察确认结果；普通按钮不盲目重试，留下 outcome_unknown。
10. 重启服务/浏览器后从库中跳转：不依赖上轮扫描进程内状态。
11. 地图版本更新或 OTA：旧运行引用固定版本，新版本重验；重命名不覆盖并行编辑。
12. 取消扫描、返回失败、条件页无法进入：保留发现结果和缺口，不宣称全部完成。

本轮评审重点：页面树是否符合使用习惯；单击查看/右键执行是否合适；开关开启/关闭与点击一次的语义；首个闭环是否满足“保存后任意起点可导航”的实际范围（已知页面或有验证过的根入口）。

## 13. v2 评审修订：以设备画面为中心

2026-09-16 根据用户截图反馈修订。本节覆盖第 4 节布局：去掉右侧选中页面的属性栏（截图中标题为“车机首页”的区域），不是删除导航根入口。左侧保存树 + 右侧放大设备画面；下方主面板改为元素检查信息，执行诊断折叠保留。

### 可行性结论与技术依据

需求可以实现。uiautomator2 提供截图、XML 层级、bounds 与 XPath 操作，元素截图可由全屏截图按 bounds 裁剪；scrcpy 提供设备画面传输与输入控制。这证明基础能力可用，但没有证明目标车机的节点完整性、权限、多屏及延迟已满足要求，也不代表浏览器接入可直接复用其桌面客户端。

来源：[uiautomator2 XPath 与截图](https://github.com/openatx/uiautomator2/blob/master/XPATH.md)、[scrcpy 官方仓库](https://github.com/Genymobile/scrcpy)。本轮完成设计及模拟交互验证，未连接车机。

### 画面模式和操作模式分别控制

- 画面模式：实时显示 / 操作后刷新。实时视频不逐帧 dump XML；选择元素时采集稳定检查快照，详情冻结该次数据。操作后刷新在动作结束并稳定后读取截图与树，也提供手动刷新。外部设备触控不会天然触发主机刷新，因此执行前仍须读取新树验证。
- 输入模式：选择元素 / 操作设备。选择模式左键只检查；操作模式左键才向设备发输入。右键始终只打开本地菜单，不发送触摸或长按。小控件可提供缩放，但缩放不改变原始坐标。
- 区分实时画面与检查快照，显示采集时间、displayId、windowId、原始尺寸、旋转和数据是否过期。视频帧、XML、截图有各自采集时间，关联到 Observation；若窗口或目标位置变化则重新获取，不承诺原子同步。

### 从画面命中元素

先减去画面在容器内的实际偏移（含 object-fit 留白），再按缩放反算屏幕坐标；超出有效画面直接拒绝。无旋转时 xDevice=(xClient-left-offsetX)/scale，yDevice 同理；旋转或显示裁剪要应用已知逆变换。匹配正确屏幕、窗口中覆盖该点的可见节点，提供父/子候选切换，区分“选中的文字节点”和“实际可点击祖先”。元素实际可点击性由 fresh tree 确认。

下方显示：元素截图、名称、所属页面、resourceId（可能为空）、XPath、bounds、中心点、class、clickable/checkable/checked、候选数、快照时间和保存位置。截图来自该次检查图裁剪，不从后续视频帧随意截取。没有结构节点时显示区域信息并标记“不支持结构定位”，不能伪造 ID 或宣称路径可稳定回放。

### 浮窗菜单

按 clientX/clientY 使用 fixed 定位，并在视口边缘翻转/约束，避免超出屏幕；支持 Escape、点击外部关闭及键盘入口。保存树中页面菜单含跳转、删除，元素菜单含到页后点击/设值、删除。删除只影响保存库，提供软删除及撤销；多入口页面按引用关系计算影响，不误删其他页面共享对象。模拟预览仅实现简单树的子项级联与撤销。

画面菜单含保存/更新元素、查看信息。保存动作不操作设备；依据固定检查快照和已有地图 revision 保存。若页面已变化，可以保存历史检查对象，但不得将其标为当前页已定位。

### 自动创建层级的必要前提

当前 XML 的父子关系是 View 容器层级，不是业务导航路径。必须从已验证导航图或本次录制的历史路径取得 pageId/edgeId 链。事务中补齐缺失页面、入口边引用和 ownerPageId，再保存元素、定位器及截图证据。名称可编辑，ID 不变，重复保存更新原对象；多路径选择一个展示路径并保存其他引用。

路径缺失时保存到“待补录入口”，不凭文本或 XML 嵌套猜测页面路线。若使用者先在车机屏幕上手动进入深层页，且平台未采集这些操作，就无法自动还原此前路径；可回到已知入口录制一遍补齐。页面截图和节点信息不能解决这一信息缺口。

### 本轮预览范围

已实现可交互模拟：放大画面、模式切换、画面元素选择、下方检查信息与示意裁剪、鼠标位置菜单、保存并补齐已知层级、更新去重、路径缺失草稿、删除与撤销。模拟库保存在当前页面会话，刷新页面会重置；正式库仍按 SQLite 设计。实机验证仍需检查坐标、截图与 XML 时差、节点缺失和输入权限。


## 14. v3 确认：不依赖 Android 系统功能键

用户确认目标车机可能不支持 Home、Back、多任务功能键。工具栏不提供这些键，移除演示专用的“打开系统设置”。连接后读取当前画面，不自动切换应用。系统设置仅为示例数据，模型应支持任意应用、多个业务入口及跨应用导航。

本节覆盖前文对 back、返回键和固定设置启动入口的假设：路径中的退出、回到上层、恢复起点，均通过已记录并验证的页面内元素或适配中明确支持的入口完成；不存在默认 Home/Back/Recent 指令，也不通过反复发送 Back 猜测恢复。页面自身提供的返回或菜单元素可以保存为普通导航边，不等同于 Android 系统功能键。

若当前页未知或没有可达路径，保留任务和证据，提示用户进入某个已知页面或补录路径；不强制拉起系统设置。启动应用等能力只能作为适配中已验证的可选入口，不是通用前提。现有探索器的 device.back() 必须在生产实现中替换为导航边执行；Adapter 的系统键方法不属于必要契约。
