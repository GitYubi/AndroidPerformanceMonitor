# 应用 / 父元素 / 子元素工作台

入口：`http://127.0.0.1:3000/ui` →「页面与元素」。旧的 4178 设计预览独立于本功能。

## 两种模式

- **操作设备**：内嵌 scrcpy H264 视频及触摸通道，支持点击和拖动，不读取控件树，不新增应用、页面或元素，也不改保存树。画面中右键不向车机发送点击，不提供 Home、返回、多任务功能键。
- **选择元素**：关闭操作会话并读取匹配的截图和控件树。点击画面即时框选、工具栏切换父子节点、右键保存。元素属性以表格显示。截图刷新开关只在选择模式可用；选择元素时切回控件树对应的检查快照。

浏览器需支持 WebCodecs（建议新版 Chrome / Edge）。不支持时会显示原因，选择元素功能仍可使用。首次进入操作模式需推送并启动设备端 scrcpy server，会有连接时间；操作期间不再等待每次 UIAutomator dump。切回标定模式仍有控件树读取等待。

## 保存流程：一棵树

1. 在应用当前画面进入选择模式，点击「添加当前应用」。自动读取包名，名称可选。
2. 选择应用，在画面中选择并保存元素。应用根画面的元素直接显示在应用下，无需先手动建立页面节点。
3. 若元素会打开新画面，在树上右键「设为父元素…」。读取入口所在画面的快照，进入操作模式点击该入口，再切回选择模式，点击「保存父元素 / 绑定打开结果」。
4. 选择这个父元素后，保存目标画面中的子元素。子元素也能继续设为父元素，形成多级路径。

父元素保留入口控件的完整原始信息：截图、ResourceId、XPath、Text、Bounds、class、包名和控件状态。点击树上的父元素可查看入口属性；打开后的画面另存为子元素的归属和导航验证依据。入口属性属于点击前的控件，不能使用目标画面的同坐标节点代替。已转换的普通元素不会在树上重复显示。

跨应用入口也可绑定：例如 AppList 的设置按钮打开 com.android.settings。目标归入设置应用，入口仍引用 AppList 中的原始控件和来源画面。名称只是别名，不用于识别设备页面。内部保留页面证据与导航边以兼容旧记录，用户维护一棵应用与元素树。

### 临时入口如何关联

从已经读取的入口画面进入操作模式，完成一次入口点击，然后切回选择模式，将结果显式绑定到父元素。操作阶段只在内存中保留临时手势，显式保存页面时才写入进入动作，首次回放逐步验证。

当前版本只自动关联**一个可可靠定位的进入动作**。从没有标定快照的位置开始、快速多步跳转、中间包含未采集页面或开关操作时，不会把历史坐标冒充稳定路径。保存时会提示补录：从父页面读取快照后单次进入目标页再保存；也可以显式勾选保留页面并标记“入口待补充”。复杂路径需分段保存中间页面。本版尚未实现自动遍历或多步后台控件采集。

应用入口通过包名启动，不强停、不清数据。启动可能恢复上次页面；实际落地页必须匹配已知页面，才能继续树上的导航。包名并不保证能直达任意子页面。

## 移动和纠错

普通子元素右键「移动到…」，选择应用下目标画面。已经绑定打开结果的父元素不能按普通叶子移动，需要重新绑定入口，避免只移动入口而留下错误的子路径。移动仅修改数据库，不操作设备，名称、定位属性和参考截图保留。

- 同应用移动：标记“待验证”。到达目标页后唯一定位成功才解除标记。
- 跨应用移动：标记“待重新标定”，拒绝沿用旧包名执行点击。右键「重新标定此元素」，在新页面选择正确元素并保存，原元素 ID 保留。
- 右键「撤销移动」恢复上一次归属和验证状态。原页面已删除时提示无法恢复。
- 删除仍为软删除，状态栏提供撤销。页面删除后关联子页面保留为应用下的可见节点。

## 身份、路径和校验

保存时不依赖用户别名判断归属。页面稳定身份保留结构、固定文字和选中标签等信息，排除 summary/widget_summary、输入字段、系统时钟、部分纯数值单位文本；不会忽略所有文字、弹窗或选中标签。

入口优先用唯一 resourceId 或属性组合。没有 resourceId 的容器会包含从子节点提取的 label（例如“电池”），不只依赖列表第几行。绝对 XPath 仍需附加属性校验。零匹配或多匹配停止，不重复输入。

旧数据首次读取时备份到 `backend/ui-data/maps-before-tree-v2.db`，保留页面、元素 ID、用户别名和原始证据，迁移到按应用分组的树。只有历史失败快照证明目的页稳定身份相同时，才把误标失效的边恢复为“待复验”，不会批量恢复全部失效路径。

父元素升级时，旧路径从历史来源快照补齐入口控件，备份保存为 `backend/ui-data/maps-before-parent-elements.db`。应用启动、滑动或缺少来源证据的旧记录不会生成虚假的 XPath，需补充控件入口。

当前身份识别仍较保守。复杂列表、布局变化、多个同结构页面、多屏等需要进一步适配；没有充分入口信息时明确显示待补充，而不是承诺可以回放。

## scrcpy 实现与运行

设备端固定使用官方 scrcpy 3.3.4，二进制及 Apache-2.0 许可证位于 `backend/vendor/scrcpy/`。服务文件缺失时运行：

```sh
bash tools/setup-scrcpy.sh
```

本地 FastAPI 通过 WebSocket 转发 H264 数据及触摸消息，浏览器用 WebCodecs 解码。设备连接与 UI 自动测试共用设备锁，断开后释放转发端口和进程。视频会话不向 SQLite 写入截图或操作树。临时操作保留在内存中，过期后清理，不跨后端重启保存。

数据仍位于 `backend/ui-data/maps.db`。当前仅支持默认显示屏、单指触摸，没有音频、剪贴板同步和系统功能键。控件证据仍存本地数据库，尚无归档清理界面。

## Midscene 导航知识复用（第一版）

测试执行器现在把已保存树作为导航知识来源之一，无需录制测试脚本。自动积累的数据按设备保存在 `backend/ui-data/navigation.db`，不自动改写用户维护的树。

- 仅处理独立导航指令，例如「进入显示页面」「打开电池页面」。包含点击、开关、输入、复合动作的任务仍交给原 Midscene 流程；「打开蓝牙」这种可能操作开关的描述不直接回放。
- 先识别当前画面，查找唯一目标及最多 12 步的已知路径。已有树中的唯一属性入口也能直接使用。重名目标不猜测。
- 每步重新定位并核验落地画面。入口消失或目的画面变化时，停用该入口，再由 Midscene 从当前实际画面完成任务；发送输入的结果不确定时终止，不自动重复点击。
- 缺少路径时正常执行 aiAct，观察 SDK 实际发送的单击。只有唯一、可点击、非开关的控件且实际画面发生变化，才形成候选入口。完整导航经 aiBoolean 确认后才保存。滑动、系统键或缺少控件证据的步骤不会伪造成可回放路径。
- 已学目标可以从其他具有完整已知路径的起点复用。暂不实现模糊语义目标检索、未知多步路径自动补全、跨应用包名启动规划、滑动入口学习。
- 敏感参数任务禁用知识读取与积累。知识更新消息不进入常规运行日志。

每个导航步骤显示复用步数、新增入口数、Midscene 调用次数及总耗时。调用次数是 aiAct / aiBoolean 接口次数，不代表底层模型请求数或 token。首次探索额外采集控件树和屏幕尺寸，可能更慢；复用仍有控件树读取开销，需以实际设备两次运行结果判断收益。测试业务断言继续独立执行，导航命中不能代替断言。

2026-09-22 模拟器验证：同一用例从设置主页执行「进入Android系统设置的显示页面」，随后独立断言亮度设置可见。首次导航 21,830 ms，Midscene 接口调用 2 次，学习 1 个入口；第二次导航 11,063 ms，复用 1 步，导航接口调用 0 次。两次用例均通过。运行 ID 分别为 `915ab77187e34e049e66563aab41c562`、`953c73ba9be44ac39bbc5880ed86aff1`。这是单条模拟器路径的实测，不代表目标车机或复杂路径；数据不包含前置启动和独立业务断言耗时。
