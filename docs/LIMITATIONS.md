# 工具能力边界、短板与改进路线

> 本文基于真实车机/手机（三星 Android 13、华为 HS7039A Android 11、高通 qcm6125 北汽车机 Android 10）的实测使用经验整理，用于明确"工具能测什么、不能测什么、短板怎么补"。

## 1. 工具定位

**适合做的**：在测试主机上通过 ADB 持续采集车机的 CPU、内存、应用渲染/呈现节奏，会话数据留档 SQLite，测试结束自动导出 ANR/Crash/Tombstone 日志，支持历史会话查看与跨机器导入。

**不适合做的**：

| 类别 | 为什么不适合 |
| --- | --- |
| 物理屏幕输出（面板响应、PWM、撕裂） | 软件指标只到 SurfaceFlinger 合成，够不到面板 |
| 纯合成器动画的实时测量（Android 10/11） | 平台没有可读的合成计数源（见短板 A1） |
| SurfaceView 渲染路径的应用帧率 | gfxinfo/HWUI 统计盲区（见短板 A3） |
| 端到端输入延迟（物理触摸→屏幕） | 软件只能覆盖"触摸事件→上屏"，面板延迟需相机 |

## 2. 应用场景对照

| 场景 | 适用性 | 推荐指标 | 说明 |
| --- | --- | --- | --- |
| 应用列表/页面滑动、菜单切换 | ✅ 适合 | R（渲染）+ P（呈现）+ J（逐帧 Jank） | 走 View/HWUI 渲染，三线联动 |
| 应用冷启动/页面转场 | ✅ 适合 | P、J、P95 帧耗时 | 转场动画由应用渲染 |
| 桌面左右滑动（纯合成层位移） | ⚠️ 12+ 可测 / 10-11 不可测 | FrameTimeline（12+） | 10/11 上应用不渲染、合成无计数源（A1） |
| 视频/导航地图（SurfaceView） | ⚠️ 受限 | 合成层统计不可用；Perfetto/相机 | gfxinfo 计数盲区（A3） |
| ANR / Crash / Tombstone 监控 | ✅ 适合 | 设备日志导出 | 测试结束自动拉取并清理 |
| 长稳测试（30/60 分钟） | ✅ 适合 | CPU/Mem 曲线、事件表 | SQLite 落盘、异常恢复 |
| 跨设备/跨版本对比 | ⚠️ 部分适合 | 稳态平均（裁剪操作首尾） | 需注意统计口径一致（A2/A4） |
| 输入响应性 | ⚠️ 部分适合 | `input_latency_ms`（仅 framestats 路径） | Android 12+ 上该字段缺失（A6） |
| 竞品黑盒对比、发布验收 | ❌ 需相机 | 高帧相机 + 光电二极管 | 软件指标到不了面板 |

## 3. 短板清单与补足方式

### A. 帧率 / 流畅度测量

**A1. 纯合成动画（桌面滑动）在 Android 10/11 无实时数据源**
- 现状：实测确认——gfxinfo 计数器不增长、framestats 返回缓存旧帧、SF `--latency` 逐字节不变、`--timestats` 空输出、`global stats` 段落（Android 12+ 才有）不存在。
- 影响：桌面/壁纸/部分系统动画的实时流畅度无法量化。
- 补足：
  - 短期：**Perfetto 交互 trace 方案化**——滑动时录制 `input/gfx/view/sched` trace，离线分析 SurfaceFlinger 合成间隔与掉帧（工具已具备采集能力，缺的是自动分析脚本）；
  - 中期：高帧相机标定桌面滑动基线；
  - 长期：车机升级 Android 12+ 后 FrameTimeline 天然覆盖。

**A2. 统计口径偏"平均/中位数"，掩盖感知卡顿**
- 现状：呈现 FPS 用间隔中位数；逐帧 Jank 用"超过 2×帧间隔"阈值。
- 影响：偶发卡顿被平均掉，p95/p99 只落库未在前端突出展示。
- 补足：前端曲线/汇总增加 **P95/P99 帧耗时**与**missed vsync 计数**展示；对逐帧源输出帧时间直方图（1s 窗口内分布）。

**A3. gfxinfo/HWUI 统计盲区（SurfaceView / TextureView / 非 View 渲染）**
- 现状：`Total frames rendered` 只统计 HWUI 路径；视频、部分导航/游戏走独立 BufferQueue，R 线恒 0。
- 影响：媒体类应用"看着流畅但 R=0"，容易误判。
- 补足：Android 12+ 依赖 FrameTimeline；10/11 依赖 Perfetto/相机；文档明确标注盲区（已在 README 说明）。

**A4. 采样窗口稀释（短操作被摊进采样窗口）**
- 现状：0.5s 间隔下，一次 0.3s 的滑动仍与静止混在一个采样点；操作时长<窗口时读数失真。
- 补足：**操作区间标记**——脚本化注入滑动（`adb shell input swipe`）并由后端记录开始/结束时间戳，分析时只统计区间内样本（见 D2）。

**A5. 手动操作与采样时间轴不对齐**
- 现状：手动滑动无时间戳，无法圈出"哪几个采样点覆盖了这次操作"，首尾帧裁剪也无从谈起。
- 补足：方案 A（脚本化操作 + 打标入库，推荐）或方案 B（`getevent -lt` 抓触摸事件流做操作边界）。

**A6. Android 12+ 上 `input_latency_ms` 缺失**
- 现状：12+ 帧率源优先走 FrameTimeline（无输入事件列），framestats 被跳过，输入延迟字段为空。
- 补足：Android 12+ 上**并行采集一次 framestats** 作为输入延迟补充源（一个额外 ADB 调用/周期）。

**A7. 触摸→上屏延迟未实现**
- 现状：只有"输入处理延迟"（HandleInputStart − NewestInputEvent）。
- 补足：扩展 framestats 计算 `DisplayPresentTime − NewestInputEvent`，落库新字段 `touch_to_display_ms`。

**A8. 多进程应用的 gfxinfo 解析可能取错段**
- 现状：`parse_gfxinfo_summary` 用 `re.search` 取第一个 "Total frames rendered"；多进程/多窗口应用可能取到不活跃进程的计数（R 线异常偏低）。
- 影响：当前这台 launcher 实测是单进程未触发，但多进程应用（常见于车机 HMI）存在风险。
- 补足：解析**所有** "Graphics info" 段，取累计帧数最大或最近增长的段。

**A9. OEM 的 FrameTimeline 输出差异**
- 现状：三星固件 present 时间全 0、Jank Type 恒 "Unknown jank"（已做 end 兜底与不计入处理）。
- 补足：持续收集各 OEM 输出建兼容矩阵；必要时在事件中提示"该设备 Jank 分类不可用，参考 framestats 口径"。

### B. 采集架构与性能

**B1. 数据源探测结果不缓存，每周期重复失败尝试**
- 现状：`capture_frame_metrics` 每个采样周期都按优先级链完整尝试（如 FrameTimeline 一直失败时每周期都白跑一次失败命令）。
- 影响：慢车机上浪费 ADB 开销。
- 补足：会话内缓存"已确认不可用"的源，失败后按退避周期重试（如每 60 周期复测一次）。

**B2. 单会话限制**
- 现状：`MonitorManager` 只允许一个活动会话。
- 影响：无法同时对多台设备采样。
- 补足：若需多设备并行，需将采样器改为按设备维度隔离（会话字典按 serial 分桶）。

**B3. 每周期 ADB 调用偏多**
- 现状：CPU 2 条 + Memory 1 条 + FPS 2~4 条（含包名查询、数据源尝试、SF latency 兜底）。
- 影响：慢车机（高通 6125 实测单条 1~2s）上周期可能被拉长。
- 补足：实测各命令耗时；包名查询改为按需（前台应用未切换时复用）；必要时对 FPS 链路降采样（如每 2 周期采一次 FPS）。

### C. 数据与分析

**C1. 无统一分析报告**
- 现状：CSV 原始数据，汇总卡只给平均/峰值/最低。
- 补足：生成会话摘要报告（HTML/Markdown）：关键指标表、逐帧统计、事件列表、日志导出清单。

**C2. 无跨会话对比**
- 现状：历史会话只能逐个查看。
- 补足：多会话指标并排对比视图（同设备/同场景的 A/B 或回归对比）。

**C3. 无 CI/无头集成**
- 现状：README 提到 CI 场景但无 CLI 无头模式。
- 补足：`--headless` 启动参数（起会话→操作→停止→输出 JSON 结果），供 CI 调用。

### D. 可用性

**D1. 设备日志导出受限于目录权限**
- 现状：`/data/anr`、`/data/tombstones` 在部分车机 shell 无读权限（实测三星拒绝）。
- 补足：多候选路径探测（`/data/anr`、`/data/tombstones`、`/data/crash`、`/sdcard/...`），失败时在事件中给出建议命令。

**D2. 无脚本化操作模板**
- 现状：手动滑动不可复现、不对齐。
- 补足：内置操作模板（滑动/点击序列 + 时长），脚本化注入并打标，实现可重复的响应性测试。

**D3. 前端无"操作区间标记"交互**
- 现状：曲线只能按时间看，无法圈出某次操作。
- 补足：前端加"标记操作开始/结束"按钮（配合 D2 脚本化自动打标更佳）。

### E. 测量边界（与高帧相机分工）

| 边界 | 软件工具现状 | 补足方式 |
| --- | --- | --- |
| 面板响应时间/亮度/PWM | 完全测不到 | 高帧相机 + 光电二极管（发布验收用） |
| 帧撕裂/合成时序偏差 | 部分（FrameTimeline present delta） | 相机标定 |
| 端到端输入延迟 | 触摸事件→上屏（可扩展 A7）；物理触摸→事件分发缺失 | 相机 + 标记物 |

## 4. 改进优先级建议

**P0（当前最值得做，收益/成本比高）**
1. A8 多进程 gfxinfo 解析修复（纯后端小改动，消除 R 线异常风险）
2. D2 脚本化操作模板 + 操作区间打标（同时解决 A4/A5/D3，可重复性核心）
3. B1 数据源失败缓存（性能优化，慢车机收益明显）

**P1（增强分析能力）**
4. A6 Android 12+ 输入延迟补充源
5. A7 触摸→上屏延迟字段
6. A2 P95/P99 与直方图前端展示
7. C1 会话摘要报告生成

**P2（规模与自动化）**
8. C2 跨会话对比视图
9. C3 CLI/CI 无头模式
10. B2 多设备并行采样
