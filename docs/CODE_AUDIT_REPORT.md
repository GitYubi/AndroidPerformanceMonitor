## 3. 问题总览

第一阶段记录 P1 2 项、P2 5 项、P3 2 项；最新汇总和补充请见第二轮。未发现并不等于不存在 P0。数量仅涵盖下文，不是全项目缺陷总数。每项按可复现影响排序；静态风险明确标识为风险。

### A01 [P1] CSV 导出静默丢失早期样本（已确认）

证据：`backend/app/storage.py:405-406` 请求 100,000 条，`backend/app/storage.py:327-330` 强制限制为 1,000 并按 ID 倒序；`backend/app/main.py:284-290` 调用该导出。超过 1,000 样本的会话只导出最近 1,000 条且无提示，可能误导后续分析。建议保留有限窗口 API，导出改用全量迭代或流式读取；风险是大数据量时内存和接口耗时。验证：构建 1,005 条样本，检查 CSV 首尾与总数，并测试大文件。

### A02 [P1] 报告缺测点被连成连续曲线（已确认）

证据：`backend/app/report.py:133-141` 过滤 `None` 后将所有有效点写入一条 polyline。缺测、进程消失等场景产生跨空洞连线，读者可能误以为中间有连续数据。建议按缺测断开线段；风险是报告视觉表现改变。验证含 `[1, None, 3]` 的 SVG 应有两个独立段。

### A03 [P2] USS 曲线时间轴失真（已确认）

证据：`backend/app/report.py:125-126` 根据索引布点；`backend/app/report.py:187-193` 保留各应用存在的快照，未把实际时间传给图表。采样间隔不等、应用退出再启动时图形会压缩空档，趋势斜率虽按时间计算，图形却不是实际时间比例。建议图表传入时间戳、按时间绘制并标记缺失与重启；风险是报告结构变化。验证构造不等间隔和跨 PID 的样本。

### A04 [P2] 导入文件无上限地读入内存（风险）

证据：`backend/app/main.py:150-155` 对上传文件执行无大小限制的 `read()`；大文件可造成后端内存压力，且后续数据库解析仍需处理。建议限制上传大小并流式写临时文件；风险是现有超大导入被拒绝。验证边界尺寸、非法 SQLite 与清理行为。

### A05 [P2] 空环境启动失败且显示已启动（已确认的配置问题）

证据：`run-local.sh:16-24` 创建 venv，依赖安装被注释，后台启动后立即打印成功，未验证进程或健康检查。新环境可能无 uvicorn；端口占用时也可能误报。建议明确安装步骤并等待健康检查；风险是启动耗时变化。验证空 venv、缺依赖和占用端口。

### A06 [P2] 高频查询反复扫描会话目录（风险）

证据：`backend/app/storage.py:174-187` 每次按 metadata 遍历查找；`client/src/pages/Home.tsx:587-599` 活跃会话每 1 秒及 3 秒轮询。历史会话很多时多条 API 重复读目录和 JSON。建议先测量，必要时建立可失效索引；风险是导入/删除后缓存失效错误。验证大量会话下请求次数与响应时间。

### A07 [P2] 报告抽稀可能遗漏末点与尖峰（已确认的算法行为）

证据：`backend/app/report.py:100-108` 等间隔取 `int(index * step)`，不保证最后一个样本或极值入图。长会话峰值和结束状态可能在图上不可见。建议保留首尾并按桶保留极值；风险是多序列点位同步。验证超过 600 点时末点及孤立峰值。

### A08 [P3] 历史备份混在正式源码（确认存在，删除前需复核）

证据：跟踪文件 `backend/app/interaction.py.pre-timeout-fix.bak` 与 `backend/app/models.py.orig`；文件名指向旧实现，但本轮未证明外部工具不读取。建议先核对历史与调用，再用版本控制保留历史；风险是外部脚本依赖。验证完整文本搜索及打包清单。

### A09 [P3] 前端页面与后端 UI 测试模块职责偏多（维护风险）

证据：`client/src/pages/UITesting.tsx` 2,106 行，`backend/app/ui_testing.py` 1,418 行，后者同时声明模型、存储、执行器和路由。行数不是缺陷本身；这些职责共同演变使修改和测试边界不清。建议在行为测试完备后按模型、执行、路由渐进拆分；风险是循环导入和接口变化。验证路由契约与执行回归。

## 新发现：证据、影响、方案和验证

### A10 [P1] 交互诊断的排他判断遗漏中间状态（模拟已复现）

- 位置：`backend/app/interaction.py:77-86,125-145`；`backend/app/monkey.py:200-207`；入口 `backend/app/main.py:298-314`。
- 证据：互斥检查只识别 `queued`、`recording`，但 `_capture` 异步经历 `pushing_config` 和 `pulling_trace`。本轮以临时目录和替身 `_adb` 暂停在 `pushing_config`，同一 serial 的第二次 `start` 被接受；未访问设备。Monkey 也复用同样不完整的状态集。
- 影响：同一设备上诊断任务可能重叠；准备或拉取期间 Monkey 互斥也可能失效，干扰录制或测试。实际硬件后果未验证。
- 建议：以 active 注册为唯一活动判据，或集中定义非终态；在同一设备锁/所有者协议下处理交互诊断、Monkey 和 UI 任务。风险：原本允许并发的流程会被拒绝。验证：对 queued、push、record、pull 各阶段模拟并发启动及取消，覆盖诊断/Monkey 两个方向。

### A11 [P2] 交互诊断后台任务和 ADB 取消清理不完整（静态风险）

- 位置：`backend/app/interaction.py:86,99-117,158-160`；`backend/app/main.py:33-50`；对照 `backend/app/adb.py:80-99`。
- 证据：`create_task` 未保存 task；`_adb` 仅处理超时，未处理 `CancelledError`；应用 lifespan 关闭 CAN、Monkey、UI、Monitor，但没有等待或取消 interaction 任务。
- 影响：退出或取消时，诊断宿主子进程可能继续运行或状态未完整持久化；不等同于已经观察到泄漏。
- 建议：保存任务句柄、关闭时统一取消并等待，复用带取消回收的 ADB 执行原语，同时保留诊断专属超时及错误信息。风险：关闭行为和 Perfetto 设备端清理时机改变。验证：用挂起的假子进程取消、关闭并检查子进程回收、状态和超时；不连接硬件。

### A12 [P2] 同一设备控件树存在两套解析和稳定性判据（语义差异已确认，影响待验证）

- 位置与调用链：地图 `ui_map.py:27-60,122-165` 的 `Device.observe → parse_tree`；执行器 `tools/ui-test/hierarchy.mjs:9-102,134-168` 的 `createTreeDevice.read → parseHierarchy`；地图页身份 `ui_map.py:63-74`，执行导航 `navigation.mjs:19-46,90-104`。
- 证据：Python 深度上限 80、Node 100；地图 label 使用子节点，Node 对无标签勾选控件还向父级查找；Python 稳定性比对签名、坐标与旋转，Node 比较另一个 fingerprint，且页面身份的数值过滤规则不同。两者服务不同功能，不能认定所有差异都是错误。

- 建议：保留各自稳定性判据，先定义共享的节点/selector 契约及黄金 XML 样本，对敏感字段、标签回退、深度边界和地图种子跨语言契约做一致性测试；再考虑生成共用规则，避免强制合并运行时。风险：身份哈希和已存导航知识兼容。验证：空标签开关、summary、旋转、动态文本、嵌套层级的 Python/Node 对照及保存→执行。

### A13 [P2] 三层重复维护 UI 步骤协议，缺少跨语言契约校验（维护风险）

### A14 [P2] ZLG 包装器吞掉所有异常并返回 None（已确认的代码行为）

- 位置：`backend/zlg/FunctionRely.py:10-23`；多个 SDK 调用使用 `backend/zlg/zlgcan.py:417` 等装饰器。

### A15 [P2] CAN 后端释放失败会跳过剩余清理（静态可达路径）

- 位置：`backend/zlg/zlgcan.py:1094-1119`；`backend/app/can_service.py:127-149`；`backend/can_adapters/hirain.py:114-120,160-169`。

- 影响：异常资源释放或断连时可能留下日志/数据库资源或无法再次尝试关闭的 SDK 资源；真实驱动行为待验证。
- 建议：分阶段 best-effort 清理并汇总错误，保留不确定的资源状态，不把失败视为成功；明确设备失联后的重试和句柄语义。风险：重复关闭厂商句柄、并发死锁。验证：对后端 close、每个 channel shutdown、DBC/log close 注入失败，核对其他资源仍释放及不重复发送。

### A16 [P2] 项目级删除与单记录删除的提交/清理策略不同（流程重复，风险待复现）

- 位置：项目删除 `backend/app/ui_testing.py:900-1009`；单 UI 记录 `ui_testing.py:1314-1336`；Monkey `backend/app/monkey.py:557-577`；性能 `backend/app/main.py:192-214`；共用工具 `backend/app/record_cleanup.py:7-29`。

### A17 [P1] 部分日志拉取失败后仍清理整个设备日志目录（替身已复现）

- 位置：`backend/app/device_logs.py:77-112`；监测结束调用链 `backend/app/monitor.py:203-207,225-247`。
