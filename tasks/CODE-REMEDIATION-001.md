## 分项整改与验收

以下各项写明实施方向和通过条件。对仍适用的反例先复现，修复后用同一入口复测并跑正常对照。静态或历史项首先核实实际入口及兼容性。

### S1 设备与数据安全

- A38 [P1] 安全传递远端 layer 参数。普通名称、空格和引号可按原名称处理，含 shell 元字符的输入作为数据处理或明确拒绝，额外命令标记不出现。
- A17 [P1] 仅清理已校验本地副本且身份仍匹配的源文件。部分拉取失败、新到文件及保留模式下的源文件仍在，正常清理只删除已确认文件。
- A34 [P1] 校验导入字段并按 HTML 上下文转义。篡改数值字段及 JSON 后输入被拒绝或安全显示，正文不生成外部输入的脚本元素，正常中文报告仍可查看和导出。
- A42 [P1] 把设备停发与资源释放从停止态写库中解耦。注入 stopping 写库失败后仍尝试停发、回收进程和句柄、释放活动登记，并可追查写库错误。

### S2 其余 P1

- A25 [P1] 保证出口最终化。停止超时、导出异常及自然结束后会话登记和连接得到清理，同设备可新建会话，落盘错误有记录。
- A36 [P1] 按会话隔离坏库。坏库与健康库并存时服务正常启动、健康数据可读，坏库被标识并保留诊断资料。
- A10 [P1] 统一同设备活动状态判定。在排队、推配置、录制和拉取阶段，两个方向的诊断与 Monkey 冲突启动均被拒绝，其他设备或任务结束后的合法操作可用。
- A01 [P1] 完整 CSV 使用全量导出。1,005 个样本逐行保留，顺序、首尾、时间戳和列正确，实时查询仍受原窗口约束。
- A02 [P1] 按缺测拆分报告折线。序列 [1, null, 3] 无跨缺测连线，连续、首尾缺测及全缺测显示正确。

### S3 生命周期与恢复

- A11 [P2] 跟踪交互诊断任务与 ADB 子进程。挂起后取消或关停，宿主进程被回收、任务终态和诊断结果可查。
- A16 [P2] 对齐项目和单记录删除的暂存、回滚及后续清理。目录权限或提交故障后能核对状态和重试，共享图片与其他项目不受影响。
- A27 [P2] 隔离各日志类型的目标目录错误。一类目录无法创建时其他类型继续成功，失败类型源文件保留。
- A35 [P2] 按依赖顺序分别尝试各管理器关停。单个管理器关闭抛错时仍调用其余应该关闭的管理器，并记录原错误。
- A41 [P2] 为完整 scrcpy 握手设截止时间。半个元数据头或断连后释放设备锁、转发和临时资源，正常视频仍可用。
- A43 [P2] 保留归档失败分段以便重启重试。注入错误后恢复启动，原始分段恰好归档一次，SQLite 与 CSV 一致。
- A45 [P2] UI 运行退出时独立释放资源。注入事件读写错误后活动占用仍释放，后续合法任务可启动。
- A52 [P2] 丢弃同会话过期响应。人为推迟 running 响应，在收到 completed 后界面仍保留终态和完整数据。

### S4 UI 执行与导航

- A12 [P2] 明确 Python/Node 控件和定位契约。用同一份 XML 验证无标签开关、敏感字段、动态文本、旋转及深度边界，地图保存的定位可在执行端消费。
- A13 [P2] 用同一组有效与无效夹具校验前端、Pydantic 和 Node。仅在未执行分支赋值的变量在运行前被拦截，双分支、默认值、循环及合法旧步骤可用。
- A22 [P2] 让图像搜索支持超时及取消。最坏合成输入下步骤按设定预算退出，常规相似度、容差及坐标与原规则一致。
- A44 [P2] 为单次运行固定基准图内容。同名替换仅影响后续运行，旧运行重复读取时摘要及 ROI 维持一致。
- A46 [P2] 按每次循环动作的时间区间聚合。两次低负载执行之间的高负载样本不计入，取消和缺结束事件有明确行为。
- A47 [P2] 回放前复验入口动作。同 resource ID 改为开关后拒绝点击，仍验证正常旧入口能够导航。
- A48 [P2] 保持页面和导航边引用一致。多层父页删除或恢复后，子页按既定规则可见、已删除的边不能回放。
- A49 [P2] 处理点击后首次读树失败。能确认位置和安全返回时完成返程；无法确认时停止并记录设备状态待确认。
- A51 [P3] 为主题存储加失败兜底。读写被拒时工作台正常呈现，当次会话可切换主题。

## 验收执行流程

1. **确认版本并复现。** 保存提交号和涉及的未提交文件摘要。复用原报告的失败夹具，修改前确认反例、修改后重复执行，并加一组正常对照。静态风险记录入口、判断条件及失败分支。
2. **逐批保存证据。** 在 tasks/CODE-REMEDIATION-001-evidence/ 按批次记录发现编号、版本、日期、环境、命令或步骤、预期、实际、退出码和证据位置。失败时记录可复现差异，修复后重跑。通过后勾选阶段并写下一步。
3. **运行离线回归。** 在拒绝连接的 ADB 替身和临时数据目录下，按[基线命令](CODE-AUDIT-001-evidence/offline.md)运行非 CAN 的后端 pytest、Node 执行器测试、pnpm check 和隔离构建。执行 python3 scripts/verify_tasks.py 与 git diff --check。CAN 用例若发生新增或改名，按已确认范围检查实际收集结果并留下排除明细。验收证据来自整改候选版本。
4. **复验 Android 模拟器。** 记录序列号、系统版本和 ro.kernel.qemu。复用[测试目录和设备步骤](CODE-AUDIT-001-evidence/android.md)，用无害标记验证 A38，用部分拉取失败验证 A17，并确认 A40 产生可拉取的 trace 且本次临时文件在失败、取消后清理。
5. **执行 Windows 原生验收。** 用整改后源码生成候选包并记录 SHA-256。按[当前候选的原生步骤](CODE-REMEDIATION-001-evidence/s8.md#v11-windows-x64-原生验证待办)，在干净 Windows x64 含中文及空格的路径运行 Start.cmd --check 与 tools/windows/smoke.py。确认包内 Python、Node、ADB 和 Sharp 可用，端口回退、同源 API、重复启动和退出清理通过。环境仍缺失时保持 V11 待验。
6. **逐项结项。** 将 50 项分别关联整改变更和证据。静态复核确认不适用的项目保存明确依据。回填 V01–V12，核对原审计和整改候选各自的版本证据。所有范围内验收通过后同步任务和索引状态并重跑校验。
